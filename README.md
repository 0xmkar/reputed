# Reputed — Human-Backed Agent Reputation on Hedera

Reputed ties every AI agent's reputation to a unique, World ID–verified human. Agents register in the ERC-8004 registries on Hedera, reviews live in the ERC-8004 Reputation Registry, and proven misconduct by an agent lowers its creator's score too. A creator cannot escape a bad score by starting over with a new wallet, because World ID allows one creator record per human.

## Stack

- **Hedera testnet** (EVM chain ID 296, JSON-RPC relay `https://testnet.hashio.io/api`, Mirror Node `https://testnet.mirrornode.hedera.com`)
- **ERC-8004** Identity Registry `0x8004A818BFB912233c491871b3d84c89A494BD9e` (0.0.7919997) and Reputation Registry `0x8004B663056A597Dffe9eCcC1965A193B7388713` (0.0.7919998), already deployed on testnet
- **World ID** for one-human-one-creator verification
- **HTS** for the non-transferable "Human-backed" credential NFT
- **HCS** for review files and score snapshots

## Run it

You need Node 22.18 or newer and pnpm 9.4 (pinned in `package.json`).

```sh
pnpm install
pnpm typecheck   # every package
pnpm test        # every package that has tests (currently the SDK)
```

### Web app (`web/`)

```sh
cp web/.env.example web/.env.local   # then set NEXT_PUBLIC_API_URL to your server (default http://localhost:4000)
pnpm --filter @reputed/web dev       # http://localhost:3000
```

Pages: `/` (home), `/explore`, `/agent/<id>` and `/creator/<address>`. The Verify and Onboard pages are built on the server side of the work split and are not there yet.

The pages read everything from the server, with no mock data, so until the server is running they show their loading state and then an error with a Retry button. Connecting a wallet needs a browser wallet such as MetaMask; the app asks it to switch to Hedera Testnet.

Only public values go in `web/.env.local`: `NEXT_PUBLIC_API_URL`, `NEXT_PUBLIC_WORLD_APP_ID` and `NEXT_PUBLIC_WORLD_ACTION`. The footer also links `NEXT_PUBLIC_CREATOR_REGISTRY`, `NEXT_PUBLIC_CREDENTIAL_TOKEN_ID`, `NEXT_PUBLIC_SCORES_TOPIC_ID` and `NEXT_PUBLIC_GITHUB_URL` when they are set.

Production build: `pnpm --filter @reputed/web build`, then `pnpm --filter @reputed/web start`.

### SDK and MCP server (`sdk/`)

```sh
pnpm --filter @reputed/sdk test
REPUTED_API_URL=http://localhost:4000 node sdk/examples/check-agent.ts <agentId>
REPUTED_API_URL=http://localhost:4000 node sdk/src/mcp.ts   # MCP server on stdio
```

Usage, the error codes and the MCP config are in [sdk/README.md](sdk/README.md); the read endpoints are in [sdk/docs/rest-api.md](sdk/docs/rest-api.md).

### Troubleshooting

- `pnpm typecheck` fails with errors in `web/.next/types` after switching branches: delete `web/.next` and run it again.
- `next dev` rewrites `web/next-env.d.ts` and may create `web/AGENTS.md`. Both are generated by Next.js; do not commit them.
